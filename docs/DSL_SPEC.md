# DSL Spec — v0.1 (live draft)

This document is the draft of the DSL shape. It is a starting point for typing the core engine — **it is expected to change** as it is implemented. When something changes here, also update `schemaVersion` and leave a note explaining why.

Format: TypeScript interfaces as reference shapes. The actual implementation lives as Zod schemas in `packages/schema`, from which these TS types are derived using `z.infer`.

```ts
interface ProjectFile {
  schemaVersion: "0.1";
  id: string;
  name: string;
  resolution: {
    width: number;
    height: number;
    preset?: "1080x1920" | "1920x1080" | "1080x1080";
  };
  fps: 24 | 30 | 60;
  tracks: Track[];
  assets: Record<string, Asset>;
}

type Track = VideoTrack | AudioTrack;

interface VideoTrack {
  id: string;
  type: "video";
  name?: string;
  clips: VisualClip[];
}

interface AudioTrack {
  id: string;
  type: "audio";
  name?: string;
  clips: AudioClip[];
}

interface AssetRef {
  assetId: string;   // reference to ProjectFile.assets
  inPoint: number;    // seconds within the source file
  outPoint: number;
}

interface VisualClip {
  id: string;
  kind: "video" | "image" | "text" | "shape";
  start: number;       // seconds on the project timeline
  end: number;

  // only if kind is "video" or "image"
  asset?: AssetRef;

  // only if kind is "text"
  text?: {
    content: string;
    font: string;
    size: number;
    color: string;
  };

  // only if kind is "shape"
  shape?: {
    type: "rect" | "ellipse";
    color: string;
  };

  // only if kind is "video" — embedded audio of the clip, editable as an audio track
  embeddedAudio?: {
    muted: boolean;
    volume: number; // 0..1
  };

  transform: KeyframeTrack<TransformState>;

  transitionIn?: Transition;   // phase 1: not implemented (only "cut")
  transitionOut?: Transition;  // phase 1: not implemented (only "cut")
}

interface AudioClip {
  id: string;
  start: number;
  end: number;
  asset: AssetRef;
  muted: boolean;
  volume: number; // 0..1, static (no volume automation over time for now)
}

interface TransformState {
  x: number;
  y: number;
  scale: number;
  rotation: number; // degrees
  opacity: number;  // 0..1
}

interface KeyframeTrack<T> {
  keyframes: Array<{
    t: number;             // seconds, relative to the start of the clip
    value: Partial<T>;
    easing: Easing;
  }>;
}

type Easing =
  | "linear"
  | "ease-in"
  | "ease-out"
  | "ease-in-out"
  | { cubicBezier: [number, number, number, number] }; // evaluate support after MVP

interface Transition {
  type: "cut" | "cross-dissolve"; // "cut" is the only one implemented in phase 1
  duration: number; // seconds
}

interface Asset {
  id: string;
  type: "video" | "audio" | "image" | "font";
  path: string;              // relative to the project file
  hash?: string;
  probedDuration?: number;
  keyframeIndex?: number[];  // I-frame timestamps, generated by the asset pipeline
  waveformPeaks?: number[];  // only for type: "audio" or video with embedded audio
}
```

## Open decisions / to be resolved during implementation

These items are not fully finalized — the core engine and server will force them to be defined. When resolved, update here:

- **Time unit**: seconds (float) was chosen instead of frames to decouple the DSL from the project's FPS. Need to confirm that this doesn't complicate frame-snapping in the UI.
- **IDs**: the format has not been defined (uuid v4 vs nanoid vs incremental). Any format works for the MVP; choose one and use it consistently throughout the DSL.
- **Track order / z-index**: it is assumed that the index of the `tracks` array defines the visual order (the last track = furthest to the front). Confirm this when implementing the DOM adapter.
- **Clip overlap validation**: "no clip can overlap on the same track" — to be implemented either as Zod validation (`.refine()`) or as a check on the server when applying the command. Define where this rule lives.
